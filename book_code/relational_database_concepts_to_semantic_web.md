The following table maps concepts from the world of relational databases to counterparts in the knowledge graph RDF world. The purpose for the comparison is to help those familiar with relational databases (which are most of my target audience) who are not familiar with knowledge graphs.

Note that I've linked many of the key words to its respective human-readable IRI (Internationalized Resource Identifier) page.


| Relational database concept     | Rough RDF / KG equivalent                         | Usually associated with           | Short explanation                                                                                                                 |
| ------------------------------- | ------------------------------------------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| [Database](https://www.wikidata.org/wiki/Q3932296)              | [Graph / dataset](https://www.wikidata.org/wiki/Q137916409)        | RDF       | A collection of RDF triples, often stored in a graph database or triplestore.                                                     |
| [Schema](https://dbpedia.org/page/Database_schema)             | Ontology / vocabulary / shapes                    | RDFS, OWL, SHACL                  | The structure and meaning of the graph: classes, properties, rules, and validation constraints.                                   |
| [Table](https://www.wikidata.org/wiki/Q278425)                | Class / type of thing                             | RDFS, OWL                         | A table such as `Employee` roughly maps to a class such as `:Employee`.                                                           |
| Row                             | Individual / resource / entity                    | RDF, OWL                          | A row such as Employee 123 maps to an individual resource such as `:Employee123`.                                                 |
| Column                          | Property / predicate                              | RDF, RDFS, OWL                    | A column such as `DepartmentID` or `Salary` maps to a property such as `:worksInDepartment` or `:baseSalary`.                     |
| Cell value                      | Object / literal value                            | RDF                               | The value in a row-column intersection becomes the object of a triple.                                                            |
| [Primary key](https://dbpedia.org/page/Primary_key)                     | [IRI / identifier](https://dbpedia.org/page/Internationalized_Resource_Identifier)          | RDF                               | A primary key identifies a row; an IRI identifies a resource in the graph.                                                        |
| [Foreign key](https://dbpedia.org/page/Foreign_key)                     | Object property / relationship                    | RDF, OWL                          | A foreign key from Employee to Department becomes a relationship such as `:Employee123 :worksInDepartment :Finance`.              |
| Lookup table                    | Controlled vocabulary / concept scheme            | SKOS                              | A lookup table such as Product Category or Job Code often maps well to SKOS concepts.                                             |
| Table hierarchy / subtype table | Class hierarchy                                   | RDFS, OWL                         | A subtype pattern such as `Employee → Manager` can map to `:Manager rdfs:subClassOf :Employee`.                                   |
| Column description              | Label / comment / annotation                      | RDFS, SKOS                        | Human-readable descriptions map to `rdfs:label`, `rdfs:comment`, or SKOS labels.                                                  |
| CHECK constraint                | Shape constraint                                  | SHACL                             | A database constraint maps to SHACL validation rules such as datatype, allowed values, or required properties.                    |
| NOT NULL constraint             | Required property                                 | SHACL                             | A required column maps to `sh:minCount 1`.                                                                                        |
| Data type                       | Datatype constraint                               | RDFS, SHACL                       | SQL datatypes map to RDF literal datatypes and SHACL datatype checks.                                                             |
| Unique constraint               | Cardinality / uniqueness rule                     | SHACL, OWL                        | Depending on intent, uniqueness may be validated with SHACL or modeled logically with OWL.                                        |
| View                            | Query-defined graph / virtual graph / named query | SPARQL, platform-specific mapping | A view can correspond to a reusable graph query or a virtual mapping from relational data into RDF.                               |
| SQL query                       | SPARQL query                                      | SPARQL                            | SQL asks questions of tables; SPARQL asks questions of RDF graphs.                                                                |
| Stored procedure                | Rule, service, application logic, or pipeline     | SWRL, SPARQL, application code    | There is no exact equivalent. Some logic may become rules, some becomes graph queries, and some stays in application or ETL code. |
| Data quality rule               | Shape / validation rule                           | SHACL                             | Data quality checks are often expressed as SHACL shapes.                                                                          |
| Master data table               | Governed entity graph                             | RDF, RDFS, OWL, SKOS              | Master data entities such as Customer, Product, Supplier, and Location often become governed graph resources.                     |
| Metadata table                  | Data catalog / semantic metadata graph            | RDF, RDFS, SKOS, OWL              | Table, column, lineage, ownership, classification, and glossary metadata can be represented directly in the graph.                |
